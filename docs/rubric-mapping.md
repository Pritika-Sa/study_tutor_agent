# Capstone Rubric Mapping

Only functionality actually implemented and tested is claimed here. Where something is implemented but not fully validated (e.g. real NCERT/NPTEL content), that distinction is stated explicitly rather than glossed over.

| Rubric Category | Implementation | Evidence |
|---|---|---|
| **React Frontend** | React 18 + React Router 6 + Axios + vanilla CSS (no Tailwind, no Next.js). 10 pages, protected routing, Context API for auth/track state. | `frontend/src/`; production build succeeds (`npm run build`); 14 passing frontend tests. |
| **FastAPI Backend** | 11 REST endpoints across auth/tutor/quiz/progress, JWT-protected, CORS configured for the frontend origin. | `backend/api/*.py`, `backend/main.py`; live CORS preflight + real cross-origin request verified with actual `Origin` headers. |
| **RAG** | PyPDFLoader -> cleaning -> RecursiveCharacterTextSplitter -> HuggingFace embeddings (local) -> ChromaDB (two structurally separate collections) -> metadata-filtered retrieval -> citation. Distance-to-similarity conversion documented and empirically verified before use. | `backend/rag/`; 15 passing tests (`test_rag.py`) covering extraction, chunking, dedup, track/subject isolation, citation honesty, insufficient-retrieval signal, real semantic (paraphrased-query) retrieval. **Real NCERT/NPTEL PDFs have not been ingested** -- all RAG testing used a hand-built, clearly-labelled synthetic PDF (`source=OTHER`). |
| **LangGraph** | 5-node `StateGraph`, shared `AgentState`, conditional routing on two independent signals (`intent`, `awaiting_retry`), checkpointed via `AsyncSqliteSaver` in the same SQLite file as the rest of the app -- verified to correctly resume a thread across two separate HTTP requests. | `backend/graph/`; 5 passing tests (`test_graph.py`) covering off-track rejection, RAG-sufficient explain, Tavily fallback with URL preservation, the ReAct iteration cap, and the full adaptive loop including the forced-stop retry limit. |
| **Agents** | Planner, Explainer, Quiz Master, Evaluator, Revision Planner -- each with a single, disclosed responsibility; none imports another's persistence layer directly. | `backend/agents/`; exercised end-to-end by `test_graph.py` and `test_api.py`. |
| **MCP** | Real MCP server as a separate OS process (stdio transport), 8 tools (5 required + 3 disclosed additions), a real MCP client agents use exclusively (never a direct `quiz_tools.py`/`progress_tools.py` import). | `backend/mcp_server/`, `backend/mcp_client/`; 14 passing tests (`test_mcp.py`) driving the real subprocess over the real protocol, not same-process function calls. |
| **Tool Use** | RAG retriever, Tavily web search, and a hand-rolled whitelisted-AST `unit_and_formula_tool` (unit conversion + safe expression evaluation) as real LangChain tools, plus the 8 MCP tools. | `backend/tools/`; `unit_and_formula_tool` deliberately not a placeholder calculator -- genuinely useful on both tracks (physics/chemistry formulas and unit conversion; aptitude/DSA arithmetic). |
| **ReAct** | Explainer's bounded Reason/Act loop: RAG (topic) -> RAG (subject-wide) -> Tavily, capped at `REACT_MAX_ITERATIONS` (default 3), a counter kept strictly separate from the adaptive quiz-retry counter. Never fabricates when both RAG and Tavily are insufficient. | `backend/agents/explainer.py`; live-verified against the real (empty) production KB and a real Tavily key -- correct fallback, correct URL preservation, correct honest "limited coverage" message when web results were also stubbed to empty in tests. |
| **External API** | Groq (LLM) and Tavily (web search), both genuinely live in this environment as of this session. | A default `GROQ_MODEL` was found to be inaccessible on the real account (404) and was replaced with a verified-working model before claiming this worked; see README §19 for the full account of what was found and fixed. |
| **Authentication** | JWT (HS256) + bcrypt password hashing; `get_current_user()` is the single source of truth for the acting student's identity on every protected route. | `backend/auth/`; 9 passing tests (`test_auth.py`); user-isolation explicitly tested (`test_user_cannot_submit_another_users_quiz`). |
| **Database** | SQLite + SQLAlchemy, 5 tables (`users`, `quiz_attempts`, `topic_progress`, `revision_plans`, `quiz_registry`), shared by the FastAPI process, the MCP server subprocess, and LangGraph's own checkpoint tables. | `backend/database/models.py`. |
| **Adaptive Learning** | Quiz -> server-side evaluation -> weak-topic detection -> re-explanation targeted at the weakest topic -> re-quiz -> mastery or a bounded forced stop -> revision plan. Verified as a real, multi-round LangGraph execution, not a simulated sequence. | `test_graph.py::test_full_adaptive_loop_and_retry_limit`; `test_api.py::test_full_end_to_end_scenario`. |
| **Testing** | 53 backend tests + 14 frontend tests, all passing together (not cherry-picked individually). Includes a genuine test-isolation bug found and fixed mid-project (documented, not hidden) and two real live-integration bugs found and fixed once real API keys were configured (also documented). | See README §19 for exact commands and results. |
| **Documentation** | This README (21 sections + architecture diagram), this rubric mapping, and `docs/demo-script.md`. | Root `README.md`, `docs/`. |

## Explicitly NOT claimed

- NCERT/NPTEL retrieval accuracy has **not** been validated against real source PDFs -- only synthetic test content.
- No manual browser click-through was performed in this session (no browser automation tool was available); the equivalent API-level flow, including real CORS headers, was verified instead.
- `npm audit`'s 7 advisories (all dev-tooling / not applicable to this client-only app) were not fixed via a forced breaking upgrade.
